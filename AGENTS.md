# AGENTS.md

## Project

Spring Boot REST API for a credit registration/lookup technical test (Fya Social Capital). Registers credits, searches them with pagination, sends an async email notification on every registration, and is protected by JWT auth + per-IP rate limiting.

Pairs with a separate Ionic/Angular frontend repo (`fya-creditos-frontend`) that consumes this API — as a web app and as a Capacitor Android app. CORS (`CorsConfig`) is configured specifically for that frontend's origins (`ionic serve`, the Capacitor Android WebView, and the deployed web build).

## Structure

```
src/main/java/com/fya/creditos/
  config/       AsyncConfig (executor for async listeners), CorsConfig, SecurityConfig (JWT + rate-limit filter chain)
  controller/   AuthController (login), CreditController (register + search) — thin, delegate to service
  dto/          Request/response shapes at the API edge — never expose entity/ classes directly
  entity/       JPA entities (Credit, User)
  event/        CreditRegisteredEvent + its @Async listener (email notification)
  exception/    GlobalExceptionHandler (@RestControllerAdvice) + the shared ErrorResponse shape
  mapper/       Entity <-> DTO mapping
  repository/   Spring Data JPA repositories
  security/     JwtAuthenticationFilter, RateLimitFilter — both are OncePerRequestFilter, wired in SecurityConfig
  service/      Business logic: AuthService, CreditService, JwtService, MailService
src/main/resources/db/migration/   Flyway migrations, V1..V5, see "Database" below
src/test/java/.../security/       Unit tests for RateLimitFilter (Mockito, no Spring context / DB needed)
```

## Commands

- Run locally: `./mvnw spring-boot:run` (export the env vars below first, or use an `.env` loader)
- Build jar: `./mvnw clean package`
- Run all tests: `./mvnw test`
- Run one test class: `./mvnw test -Dtest=ClassName`
- Docker build: `docker build -t fya-creditos-backend:local .`
- Docker run: `docker run -d -p 8080:8080 -e SPRING_DATASOURCE_URL=... [...] fya-creditos-backend:local`

Required env vars are in `.env.example`. Key ones: `SPRING_DATASOURCE_URL/_USERNAME/_PASSWORD` (Neon Postgres), `MAIL_HOST/_PORT/_USERNAME/_PASSWORD/_SENDER/_NOTIFICATION_RECIPIENT` (SMTP), `JWT_SECRET`.

## Conventions

- Layering: `controller` → `service` → `repository`/`mapper`. Controllers stay thin; validation happens on the DTOs via Bean Validation (`jakarta.validation`), business rules in the service layer.
- DTOs at the edge, always — `entity/` classes never appear in a controller signature or get serialized directly.
- Errors go through `GlobalExceptionHandler` (`@RestControllerAdvice`), returning the shared `ErrorResponse(timestamp, status, message, errors[])` shape. Filters that reject a request *before* Spring MVC dispatch (`JwtAuthenticationFilter`'s 401, `RateLimitFilter`'s 429) build that same shape manually, since `@RestControllerAdvice` only catches exceptions from controller-dispatched requests, not filter-level rejections.
- Money is `BigDecimal`, never `double`/`float`.
- Timestamps are `Instant`/`TIMESTAMPTZ`, never naive `LocalDateTime`/`TIMESTAMP` (see `V3` migration) — avoids local-dev-vs-cloud-deploy timezone ambiguity.
- New Spring beans that need JSON serialization inside a filter should build their own `ObjectMapper` (with `JavaTimeModule` registered) rather than injecting one — `spring-boot-starter-webmvc` (Spring Boot 4's renamed starter) doesn't expose an auto-configured `ObjectMapper` bean the way the old `spring-boot-starter-web` did. See `RateLimitFilter` for the pattern.

## Database

Flyway, migrations in `src/main/resources/db/migration`. **Applied migrations are immutable** — any schema change is a new `V{n}__description.sql` file, never an edit to an existing one. `spring.jpa.hibernate.ddl-auto=validate` — Hibernate never auto-generates schema, only validates it matches.

| Migration | Content |
|---|---|
| `V1` | `credits` table |
| `V2` | Seeds the 10 credits from the test's annex |
| `V3` | `registered_at` → `TIMESTAMPTZ` |
| `V4` | `users` table |
| `V5` | Seeds 3 test users (bcrypt, password `password123` for all three) |

## Do not touch

- Applied Flyway migrations (`V1`-`V5`) — add a new migration instead of editing.
- `android/` in the *frontend* repo — generated by Capacitor, regenerates via `npx cap sync android`.
- `keystore.properties` / `*.keystore` in the frontend repo — gitignored on purpose, never commit real values.
- `target/` (Maven build output).

## Environment gotchas

- **JDK 21 required.** Spring Boot 4.1.0 and the Maven build target it explicitly.
- **Render free tier sleeps after ~15 min idle** — first request after that takes 30-60s to wake up. Not a bug.
- **Render blocks outbound SMTP on ports 25/465/587** — production uses Brevo's relay on port 2525 instead (`MAIL_HOST`/`MAIL_PORT` env vars). Locally/Docker this restriction doesn't apply.
- **No Spring profiles** (no `application-dev`/`application-prod`) — the same jar/image runs everywhere; only env var values differ between local, Docker, and Render.
- **`RateLimitFilter` is in-memory, per-instance** — fine for a single Render instance with no horizontal scaling. If this ever runs on multiple instances, the bucket state needs to move to something shared (Redis, etc.) or each instance will have its own independent limit.
- **The `ObjectMapper` bean gotcha above** — don't assume `@Autowired ObjectMapper` works everywhere; it wasn't available when `RateLimitFilter` needed it.
